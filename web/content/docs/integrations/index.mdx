title: Integrations
description: Every tool Reckon can connect, grouped by area, with its connection provider, CLI and read-only mode.
---

Reckon runs existing CLIs. It does not wrap them in a new binary. Each tool is a
connection **provider**: you add a connection with
`reckon connect <name> --provider <provider>`, and the agent reaches it with
`reckon run <connection-or-provider> -- <the CLI's own arguments>`.
`reckon connect --list` prints the same list with each provider's required
settings.

Each provider has one of three modes:

| Mode | Meaning |
| --- | --- |
| **own** | The CLI enforces read-only itself. Reckon switches that mode on and refuses flags that would change the target, credentials or safety. |
| **allowlist** | The CLI has no read-only mode. Reckon allows only listed read commands. |
| **approval** | The agent must ask you before each run. Claude Code's settings in the org folder mark these runs as ask. |

## Development

| Provider | CLI | Mode | What it covers |
| --- | --- | --- | --- |
| `jenkins` | `jenkins` | own | Jobs, builds, stages, test reports, console logs |
| `github` | `gh` | allowlist | Pull requests, Actions runs, releases, issues |
| `kubernetes` | `kubectl` | allowlist | Pods, deployments, events, rollout history |
| `aws` | `aws` | allowlist | CloudWatch metrics and logs, load balancers, SQS, ECS |

## Operations

| Provider | CLI | Mode | What it covers |
| --- | --- | --- | --- |
| `cubeapm` | `cubeapm` | own | Traces, PromQL metrics, LogsQL logs, dependencies |
| `grafana` | `grafana` | own | Alerts, silences, annotations, dashboards, datasources |
| `elasticsearch` | `es` | own | Cluster health, indices, Query DSL and SQL search |
| `nginxpm` | `nginxpm` | own | Proxy hosts, redirections, streams, certificates, audit log |
| `postgres` | `psql` | approval | Active queries, locks, plans, replication |
| `mysql` | `mysql` | approval | Sessions, plans, InnoDB state, replication |
| `mongodb` | `mongosh` | approval | Running operations, replica set state, bounded samples |
| `clickhouse` | `clickhouse client` | approval | Tables, query log, metrics, events |
| `redis` | `redis-cli` | approval | Memory, latency, slow log, keyspace size |
| `kafka` | `kcat` | approval | Cluster metadata, group-less topic reads |
| `kafka-rpk` | `rpk` | approval | Consumer-group lag, cluster and topic state |

| `clarity` | `clarity` | own | Dashboard exports, session recordings, analytics questions |

## Growth

| Provider | CLI | Mode | What it covers |
| --- | --- | --- | --- |
| `gsc` | `gsc` | own | Google Search performance, trends, opportunities, URL inspection |
| `bing` | `bwt` | own | Bing traffic, queries, pages, crawl health |

<Callout type="warn">
  Read-only is a combination of the CLI's own mode, Reckon's argument checks,
  approval prompts and the account's permissions on the server. Give every
  connection the least-privileged account that can read what you need.
  Database users must be true read-only roles.
</Callout>
