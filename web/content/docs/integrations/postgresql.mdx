## What it covers

Use PostgreSQL only after other evidence points to a table or query. `psql` can
confirm session safety, show active queries and waits, find ungranted locks,
examine a slow plan and measure replication lag.

## Connect

```bash
reckon connect pg-prod --org acme --provider postgres --for-env prod
```

Fill in `~/.reckon/orgs/acme/secrets/pg-prod.env` with a read-only role:

```bash
PGHOST=db.example.com
PGPORT=5432
PGUSER=readonly
PGPASSWORD=replace_me
PGDATABASE=app
PGSSLMODE=require
```

`PGHOST` and `PGUSER` are required. There is no `reckon login` for databases.

`reckon verify pg-prod` runs `psql -c "SELECT 1"`.

## Read-only contract

PostgreSQL is an **approval** connection: the agent must ask you before each
run, and Claude Code's settings in the org folder mark every
`reckon run pg-prod` or `reckon run postgres` as ask. Read each query before you
allow it.

- **The role is the real barrier.** `PGUSER` must be a true read-only role;
  it is the only layer that denies writes on every path.
- **Reckon applies session read-only.** Each run gets
  `PGOPTIONS='-c statement_timeout=30s -c default_transaction_read_only=on'`.
  This stops accidents, not a determined write: a session can opt back into
  read-write, so never allow `SET ... READ WRITE`,
  `SET default_transaction_read_only=off` or `BEGIN READ WRITE`.
- Reckon refuses `-h`, `--host`, `-U`, `--username`, `-p` and `--port`, and
  any connection string (`postgres://...` or `host=...`) in place of a
  database name, and a second positional word (psql would read it as the user).
- `EXPLAIN` before any non-trivial query and put `LIMIT` on every `SELECT`
  (default 100). `EXPLAIN ANALYZE` executes the query.

## Key commands

```bash
reckon run postgres -- -c "SHOW default_transaction_read_only;"
reckon run postgres -- -c "SELECT pid, state, wait_event_type, wait_event, now()-query_start AS dur, query FROM pg_stat_activity WHERE state != 'idle' ORDER BY dur DESC LIMIT 20;"
reckon run postgres -- -c "SELECT relation::regclass, mode, granted, pid FROM pg_locks WHERE NOT granted LIMIT 100;"
reckon run postgres -- -c "EXPLAIN <query>;"
```

The first command must report `on`.
