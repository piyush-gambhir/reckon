---
title: Setup
description: Install Reckon and its CLIs on macOS or Linux, put the reckon command on your PATH, and migrate an older checkout.
---

Reckon needs Python 3.9 or newer (no packages) and Claude Code or Codex. The
checkout holds Reckon's code only. Orgs, credentials, knowledge and saved work
live under `~/.reckon` (or `$RECKON_HOME`).

## macOS and Linux

```bash
git clone https://github.com/piyush-gambhir/reckon.git
cd reckon
bash scripts/setup.sh
export PATH="$HOME/.reckon/bin:$PATH"     # add this to your shell profile
```

`setup.sh` installs missing tools with Homebrew on macOS and `apt` or `dnf` on
Debian, Ubuntu, Fedora and RHEL-family systems. Downloaded binaries such as
`rpk` and `kubectl` are checksum-verified. It then creates `~/.reckon` (mode
0700) and links `~/.reckon/bin/reckon` to `scripts/reckon.py` in the checkout.
Other Linux distributions get manual-install guidance.

<Callout type="info">
  Setup is idempotent. Re-running it installs only what is missing and leaves
  existing tools and orgs alone.
</Callout>

Once you have created an org, `reckon doctor` reports the Python version,
whether `~/.reckon` is private, your orgs, connections without credentials or
without their CLI, and the default context.

## Windows

Use WSL2 and the same script inside it:

```powershell
wsl --install
```

Native PowerShell (`scripts\setup.ps1`, `scripts\reckon.ps1`) is experimental.
`reckon open` needs symlink rights there (Developer Mode).

## Where data lives

```text
~/.reckon/
  bin/reckon                  link to the checkout's scripts/reckon.py
  context                     default org/env for the next launch (reckon use)
  orgs/<org>/
    org.json                  environments and connections, no secrets
    secrets/<connection>.env  credentials, 0600, never shown to the agent
    config/<connection>/      the CLI's own config and saved logins
    runtime/<connection>/     private HOME, cache and temp for that CLI
    workspace/                the agent's folder for this org
      RECKON.md               generated: environments and connections
      CLAUDE.md, AGENTS.md    the org's agent guide; add your own notes
      knowledge/              company and per-environment facts
      sessions/               saved work with evidence
      incidents/              promoted RCAs
```

Next, create an org and connect its tools: see
[Orgs & connections](/docs/connections) or the [Quick start](/docs/quickstart).

## Migrate an older checkout

Older versions kept one business inside the checkout: `.env.<env>` files,
`.config/<env>/`, `infra-knowledge/`, `sessions/` and `incidents/`.
`reckon migrate` copies that layout into a new org. It changes and deletes
nothing in the old checkout.

```bash
reckon migrate --org acme --rename production=prod --rename staging=dev --share cubeapm --dry-run
reckon migrate --org acme --rename production=prod --rename staging=dev --share cubeapm
```

- `--rename OLD=NEW` renames an environment. The new defaults are `prod`, `uat`
  and `dev`.
- `--share TOOL` makes one connection for every environment, for example
  CubeAPM when one server holds them all. It needs identical settings and saved
  CLI config in every environment, and fails otherwise. A tool that is
  identical everywhere is shared automatically; any other tool becomes one
  connection per environment, such as `jenkins-prod` and `jenkins-dev`.
- `--from PATH` reads another checkout (default: this one). `--name` sets the
  org's display name.
- Settings that use shell expansion (`$(...)`, `${...}`) are skipped and listed
  by name. Copy those by hand into the new secrets files.

A shared CubeAPM connection still needs its environment labels:

```bash
reckon connect cubeapm --org acme --label prod=PROD --label dev=DEV
reckon use acme/prod
reckon verify
```

Once you have checked the new org, delete the old files from the checkout.

## Pinned CLI releases

Setup builds the nine CLIs maintained alongside Reckon with `go install` (it
installs Go first if needed) at the versions pinned in
`scripts/cli-releases.csv`, and installs each under its public name. A command
already on your PATH is left in place.

| CLI | Release |
| --- | --- |
| `grafana` | 0.2.10 |
| `jenkins` | 0.2.10 |
| `cubeapm` | 0.2.11 |
| `es` | 0.1.11 |
| `jira` | 0.1.12 |
| `nginxpm` | 0.1.12 |
| `gsc` | 0.1.6 |
| `bwt` | 0.1.6 |
| `clarity` | 0.1.4 |

The other tools (`aws`, `gh`, `kubectl`, `psql`, `mysql`, `mongosh`,
`clickhouse`, `redis-cli`, `kcat`, `rpk`, `jq`) come from your package manager
or vendor releases.
